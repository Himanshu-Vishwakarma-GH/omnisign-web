### 9.2 What the model files actually contain (vs v2 assumptions)

- Temporal model: Keras 3 Functional, input **[null, 30, 126]** (hand
  landmarks only — 21 left + 21 right × 3), output **263 classes**
  (label_map.json). NOT [30,225] / 278 as the v2 rebuild assumed from the
  README. Architecture: Dense frame projection (126→128) → trainable
  PositionalEncoding (pos_embedding [1,30,128]) → 2× TransformerEncoderBlock
  (d_model 128, 4 heads, d_ff 256, dropout 0.3) → LayerNorm →
  GlobalAveragePooling1D → Dense 64 (relu) → Dense 263 (softmax).
- Static model: plain Dense stack, input [null, 126], output 36 classes
  (0–9, A–Z). No custom layers.
- `temporal_label_map.json` (307 entries, lowercase, first key
  'isl daily words') does NOT match any model output — not used.
  `label_map_holistic_v2/v3.json` (261 labels) do NOT match the 263-output
  model — not used. Only `label_map.json` (263) and
  `static_label_map.json` (36) are wired in.
- Calibration file: temperature T=1.05, ECE 0.034 ("already
  well-calibrated"); applied to output probabilities as p^(1/T).

### 9.3 Loading — what stock TF.js could NOT do, and the fixes

1. `tf.loadLayersModel` fails on both models: "An InputLayer should be
   passed either a `batchInputShape` or an `inputShape`" (Keras 3 uses
   `batch_shape`), then "Corrupted configuration, expected array for
   nodeData" (Keras 3 `inbound_nodes` use {args:[__keras_tensor__]}
   instead of Keras 2 [[name, node, tensor, {}]]).
2. Fix: `patchTopology` (src/lib/lexisight.ts) rewrites the topology in
   memory (batch_shape → batch_input_shape, dtype DTypePolicy dict →
   string, inbound_nodes conversion, input/output_layers wrap, drop
   build_config). Downloaded files are untouched.
3. The weights manifest uses bare duplicate names ('kernel', 'bias'),
   so stock weight mapping fails ("Provided weight data has no target
   variable: kernel"). Fix: build the model from topology only
   (`tf.models.modelFromJSON`), then assign the .bin weights by
   SHAPE-group FIFO order (`assignWeightsFromManifest` in tfjsClient.ts).
   Verified: TF.js orders model.weights trainable-first (BatchNorm
   moving stats last) while the manifest interleaves them — within each
   shape group the order is identical (diagnosed explicitly for the
   static model; temporal has no BatchNorm).
4. Custom layers: `PositionalEncoding` and `TransformerEncoderBlock`
   (src/lib/lexisightLayers.ts) re-implemented from the topology +
   weights-manifest shapes alone (Q/K/V kernels [128,4,32], output
   [4,32,128], FFN [128,256]→[256,128], 2 LayerNorms/block). Weight
   creation order matches the manifest order. Norm placement is
   POST-norm (keras.io pattern) — UNVERIFIED; a PRE-norm variant was
   also load-tested in Node (both produce plausible outputs, so the
   variant could not be discriminated from the files alone).
